# 当前部落战与最近战争设计

> 状态：第一版已实现，待部署和真机验收。
>
> 本文描述微信小程序「战斗 → 部落战」的当前战争和每部落最近 15 场已结束普通战争，并与数据库、API、前端、调度和运维文档保持同步。

部落战内容区使用下拉菜单切换“当前部落战 / 某个具体部落的最近15场”。历史选项显示完整部落名和业务分类，不按分类合并，因此多个互刷部落可以单独选择。当前视图保持原有全部自有部落汇总与单部落详情，并按分钟读取后端缓存；历史视图只在进入时从 `war_history_cache` 读取一次轻量列表，顶部下拉菜单确定部落，筛选面板只限定胜、平、负。点击后复用同一详情宽表，不执行分钟轮询。历史记录按部落分别保留 15 场，CWL 不进入普通战争历史。

## 1. 目标与页面层级

在小程序中展示全部自有部落的当前战争，并允许进入单个部落查看双方成员、出刀和防守汇总表。

第一版采用两级页面：

1. **汇总页**：显示所有自有部落的当前战争摘要，支持筛选。
2. **单部落详情页**：显示某一部落当前战争的完整宽表，并作为单部落分享落地页。

汇总卡片始终按 `config/settings.yaml` 中 `coc_sync.clans` 的配置顺序展示，从战营开始依次向下排列。战争状态变化和筛选操作只影响卡片内容或可见性，不得重新排列剩余部落，避免同一部落在刷新后跳动位置。

汇总页不同时渲染多张 50 行宽表，避免微信小程序出现节点过多、滚动冲突、列宽失效和右边界裁剪。

## 2. 范围

### 2.1 部落范围

读取 `config/settings.yaml` 中 `coc_sync.clans` 下所有 `enabled: true` 的部落：

| category | 中文分类 | 当前数量 |
|---|---|---:|
| `combat` | 战营 | 1 |
| `normal` | 混营实战 | 2 |
| `flat` | 偷矿 | 1 |
| `farm` | 互刷 | 8 |

按当前配置默认共 12 个部落。名称、标签、分类和顺序均以配置为准，不在前后端重复硬编码。

### 2.2 战争范围

- 「部落战」仅展示普通部落战。
- 优先使用官方战争类型字段判断 CWL；字段缺失时可将 `attacksPerMember = 1` 作为辅助判断。
- 检测到 CWL 时显示“当前正在进行联赛，请前往联赛 → 战斗日查看”，不在本页面渲染普通部落战表格。
- 联赛战斗日属于后续「联赛 → 战斗日」功能范围。

### 2.3 访问范围

- 所有小程序用户都可查看，不要求绑定游戏账号。
- COC API Token 只能存在于后端环境变量中，绝不返回给小程序。
- 后端只允许查询配置中的已启用自有部落，不能把任意外部部落标签透传到 COC API。

## 3. 页面设计

### 3.1 战斗主页面

```text
战斗                         ⚔️部落战  🏆联赛
------------------------------------------------
```

默认打开「部落战」。部落战内容区提供筛选入口，避免改变「部落战 / 联赛数据」二级导航的含义。

### 3.2 汇总页

汇总页默认显示全部 12 个部落的战争摘要。单张卡片建议包含：

- 分类、部落名称和标签
- 状态：准备日、战斗日、已结束、当前无战争、同步失败
- 对手名称和标签
- 双方已用刀数 / 总刀数
- 双方星数和摧毁率
- 当前领先、落后或平局
- 开战或结束倒计时
- 数据更新时间
- 详情和单部落分享入口

无战争和同步失败必须分开显示。单个部落请求失败不得阻塞其他部落。

摘要卡排序：战斗日、准备日、已结束、CWL、当前无战争、待同步、同步失败；同一状态内沿用配置顺序。

### 3.3 筛选

筛选面板复用部落成员页已验证的底部弹层交互，支持：

1. 分类多选：战营、混营实战、偷矿、互刷。
2. 具体部落多选：显示“部落名称（标签）”。
3. 状态筛选：全部、战斗日、准备日、已结束、当前无战争、同步失败。
4. 全选、清除、取消、确定。

初始状态为四类和全部部落均选中。

### 3.4 单部落详情页

```text
← 当前部落战
------------------------------------------------
部落战 · 战斗日 · 当前结果：平局
我方部落名称 VS 对手部落名称
#我方标签      #对方标签
开战时间 / 结束时间 / 倒计时
我方：69/100刀 · 150星 · 100%
对方：86/100刀 · 150星 · 100%
------------------------------------------------
横向滚动的双方成员汇总表
```

双方按照 `mapPosition` 对齐，每行同时显示相同地图序号的我方和对方成员。不得按星数或摧毁率重排，以免破坏对位关系。

## 4. 详情表字段

```text
序号
├── 我方：名称 / 大本 / 第一刀 / 对位 / 第二刀 / 对位 / 防守 / 对位 / 防守次数
└── 对方：名称 / 大本 / 第一刀 / 对位 / 第二刀 / 对位 / 防守 / 对位 / 防守次数
```

| 字段 | 含义 |
|---|---|
| 序号 | 成员的 `mapPosition` |
| 名称 | 玩家名称 |
| 大本 | 当前战争数据中的大本等级 |
| 第一刀 | 第一笔攻击的星数和摧毁率 |
| 第一刀对位 | 目标成员的地图序号 |
| 第二刀 | 第二笔攻击的星数和摧毁率 |
| 第二刀对位 | 目标成员的地图序号 |
| 防守 | 对该基地造成的最佳攻击结果 |
| 防守对位 | 取得最佳结果的敌方地图序号 |
| 防守次数 | 被三星次数 / 总共被进攻次数 |

攻击按照官方 `order` 升序排列。未出刀显示“未出刀”。

### 4.1 防守次数

定义已确认：

```text
被三星次数 / 总共被进攻次数
```

例如 `2/5` 表示共被进攻 5 次，其中 2 次被三星。重复三星全部计数。

- 筛选 `defenderTag` 等于该成员标签的完整攻击明细。
- 分母为筛选后的攻击总数。
- 分子为其中 `stars == 3` 的数量。
- 可与官方成员字段 `opponentAttacks` 做一致性校验；不一致时以完整攻击明细为展示依据并记录警告。
- 未被攻击时，防守和对位显示 `-`，次数显示 `0/0`。

### 4.2 最佳防守结果

“防守”列表示敌方对该基地取得的最佳攻击结果：

1. 星数更高者优先。
2. 星数相同时，摧毁率更高者优先。
3. 两者均相同时，取更早发生的攻击。

防守对位通过最佳攻击的 `attackerTag` 映射到敌方 `mapPosition`。

## 5. 状态与结果

| 官方状态 | 页面状态 | 时间信息 |
|---|---|---|
| `preparation` | 准备日 | 距离开战时间 |
| `inWar` | 战斗日 | 距离结束时间 |
| `warEnded` | 已结束 | 最终结果 |
| `notInWar` / 无有效数据 | 当前无战争 | 不渲染详情表 |

结果先比较星数，星数相同再比较摧毁率。准备日显示“尚未开战”，战斗日显示“当前领先 / 当前落后 / 当前平局”，结束后显示“胜利 / 失败 / 平局”。

总刀数为 `teamSize × attacksPerMember`；已用刀数读取双方汇总攻击数。

## 6. 数据来源与转换

后端通过已有 `CocApiClient` 的官方域名白名单访问：

```text
GET /clans/{clanTag}/currentwar
```

主要字段：

- 战争：状态、`teamSize`、`attacksPerMember`、战争类型、开始和结束时间。
- 双方：名称、标签、星数、摧毁率和已用攻击数。
- 成员：标签、名称、`mapPosition`、`townhallLevel`、`opponentAttacks`、攻击列表和最佳敌方攻击。
- 攻击：`attackerTag`、`defenderTag`、`stars`、`destructionPercentage`、`order`。

注意：`currentwar` 的成员字段为 `townhallLevel`（小写 `h`），不能误用成员列表接口的 `townHallLevel`。

后端负责验证部落标签、识别普通战争/CWL、建立标签到序号的映射、拆分第一/第二刀、计算最佳防守和防守次数、计算战争结果，并标准化错误状态。前端只展示标准化数据和计算本地倒计时。

## 7. 缓存与刷新

调度任务每 2 分钟醒来一次，但按每个部落的缓存状态分别限频：

| 缓存状态 | 官方 API 刷新周期 |
|---|---:|
| 战斗日 `in_war` | 2 分钟 |
| 准备日 `preparation`，距开战超过 30 分钟 | 30 分钟 |
| 准备日 `preparation`，距开战不超过 30 分钟 | 2 分钟 |
| 无战争 `not_in_war` | 5 分钟 |
| 已结束 `war_ended` | 5 分钟 |
| CWL 跳转提示 `cwl` | 30 分钟 |
| 同步失败 | 5、10、20、30 分钟逐级退避，最高 30 分钟 |

- 新增独立当前战争调度任务，由 `scripts/scheduler.py` 管理，不启动额外常驻进程。
- 每次从配置读取已启用部落，只请求达到各自刷新周期的部落。
- `cwl` 仅表示普通部落战接口识别到当前战争属于联赛并显示跳转提示；联赛实时看板仍使用独立的 `cwl_live` 周期。
- 单个部落失败只记录该部落错误，其他部落继续同步。如果该部落已有成功快照，保留上次战争数据和战争状态，只更新 `error`、`attempted_at` 和连续失败次数。API 通过 `is_stale`、`sync_error`、`sync_attempted_at` 和 `sync_failure_count` 暴露该状态，前端显示“当前展示缓存数据”警告，不再把可用卡片替换为整卡失败。只有尚无任何成功快照时才返回 `status=error`。
- 缓存额外记录 `attempted_at` 和连续失败次数，成功后清零失败次数。
- `python scripts/scheduler.py --once current_wars` 仍会忽略状态限频并立即全量刷新。
- API 路由只读缓存，不在普通页面请求中同时访问 12 次官方接口。
- 前端进入页面、返回前台时读一次缓存；长时间停留时每 1 分钟重新读取。
- 前端轮询只访问后端缓存，不增加 COC 官方接口调用量。
- 倒计时根据服务端时间字段每秒本地更新，不产生网络请求。

缓存保存部落标签、名称、分类、战争状态、标准化 JSON、同步时间和错误；表结构见 `docs/02-database.md`。

## 8. API

```text
GET /api/clan/current-wars
GET /api/clan/current-wars/{clan_tag}
```

汇总接口返回全部配置部落的摘要、状态和筛选元数据；详情接口返回单个部落的战争概要和双方对位行。

详情接口先用配置白名单验证 `clan_tag`，再读取缓存。未验证的路径参数不会交给外部 API；响应 JSON 已由后端测试固定并接入前端。

## 9. 分享

- 小程序右上角菜单分享全部部落汇总页。
- 部落摘要卡的分享按钮分享单个部落详情页。

单部落分享使用独立非 TabBar 页面，例如：

```text
/pages/war/current-detail?clan_tag=%232QQ
```

接收者只看到该部落的最新当前战争。分享的是入口，不是数据快照。

## 10. 微信小程序表格约束

必须遵守 `docs/11-uni-app.md`、`docs/14-farm-clans.md` 和 `docs/CHANGELOG.md` 中已验证的规则：

1. 使用普通 `<style>`，禁止 `<style scoped>`。
2. 每行显式设置 `display: flex` 和 `flex-direction: row`。
3. 单元格使用固定宽度、`flex-shrink: 0` 和 `box-sizing: border-box`。
4. 不嵌套横向和纵向 `scroll-view`。
5. 不给 `scroll-view` 本身添加 padding，间距放在普通容器。
6. 内部容器、表头和每一行使用相同的明确总宽度。
7. 使用 `.table-body` 撑满宽表背景，避免右边界和背景被裁剪。
8. 第一版不冻结首列、冻结表头或使用复杂 `sticky`。

详情页让页面承担原生纵向滚动，只为完整表格设置一个 `scroll-view scroll-x`。横向区域同时包含表头和所有行，不再创建内部纵向 `scroll-view`。

汇总页最多渲染 12 张摘要卡；详情页只渲染一场战争，最多约 50 行，避免一次生成多场战争的一万多个单元格节点。

## 11. 错误与边界情况

| 场景 | 展示方式 |
|---|---|
| 当前无战争 | 显示“当前无部落战”，不渲染详情表 |
| 当前为 CWL | 提示前往“联赛 → 战斗日” |
| 战争数据不可访问 | 显示“无法获取当前部落战”，保留同步错误 |
| 单个部落超时 | 仅该部落标记同步失败 |
| 成员未出刀 | 攻击列显示“未出刀” |
| 基地未被攻击 | 防守显示 `-`，次数显示 `0/0` |
| 官方返回未知标签 | 对位显示 `-` 并记录警告 |
| 缓存尚未生成 | 显示“数据正在同步，请稍后重试” |

## 12. 验证计划

后端验证：

- 准备日、战斗日、已结束、无战争和 CWL 状态转换。
- 第一刀、第二刀按照 `order` 排序。
- 玩家标签与双方地图序号映射。
- 重复三星全部计入防守次数，例如 `2/5`。
- 最佳防守的星数、摧毁率和时间顺序比较。
- 5v5、15v15、30v30、50v50 数据。
- 单个部落失败不影响其他部落。
- 非配置部落标签被拒绝。

前端验证：

- 四类和具体部落多选筛选。
- 摘要状态、倒计时、详情跳转和单部落分享。
- 详情表横向滚动、长昵称和 50 行渲染。
- 小屏设备、iOS 真机、Android 真机和开发者工具。
- 表格最右边界、背景、列宽和行高一致性。
- 页面隐藏后停止倒计时和缓存轮询，重新显示时恢复。
- `npm run build:mp-weixin` 生产构建成功。

## 14. 第一版已采用的默认值

第一版采用以下默认值：

- 汇总卡按战斗日、准备日、已结束、CWL、当前无战争、待同步、同步失败排序。
- `warEnded` 显示最终胜利、失败或平局，直到官方状态切换。
- 进攻三星绿、二星黄、零至一星红；防守语义反向。
- 筛选入口位于部落战内容区操作栏，顶栏只保留部落战/联赛数据二级导航。

这些细节不改变已确认的核心架构：全部 12 个自有部落、四类筛选、汇总页 + 单部落详情页、普通部落战与 CWL 分流、重复三星全部计数、单部落分享、所有用户可查看，以及后端按战争状态和开战时间动态更新、前端每 1 分钟读取缓存。
