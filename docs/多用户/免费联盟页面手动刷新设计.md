# 按需刷新套餐的页面主动刷新与低频保底设计

状态：已实现；部署状态以当前运行版本为准

适用范围：普通联盟浏览页面；平台超级管理入口保持独立

最后更新：2026-10-18

## 1. 目标

免费版和普通会员保留低频自动同步，同时允许正在浏览数据的用户通过进入页面、点击按钮或在列表顶部继续下拉，
主动申请刷新当前页面对应的实时资源。所有主动刷新只向统一同步队列提交任务，不在 HTTP 请求中直接
调用 COC API。

本功能采用以下核心规则：

1. **能合法打开页面，就能申请刷新该页面的数据。** 不再要求访问者必须加入联盟，也不要求拥有联盟管理权限。
2. **页面访问范围就是刷新范围。** 后端必须复用页面 GET 接口的联盟浏览上下文，不能接受任意联盟或任意部落标签。
3. **公共资源全局去重和冷却。** 同一 `resource_type + resource_key` 在全部联盟、用户和分享访客之间只产生一份任务。
4. **刷新不提升权限。** 刷新完成后，访问者仍只能看到原本允许查看的字段；管理字段和操作权限不变。
5. **免费版和普通会员展示页面级主动刷新。** 高级会员和内部联盟使用后台自动刷新策略，不重复展示手动提交入口。
6. **进入页面只检查一次。** 页面进入时若资源已经过期则提交任务；命中冷却或已有开放任务时直接使用缓存，
   停留在页面不会按冷却间隔持续创建任务。
7. **首次订阅立即初始化。** 首次订阅部落时提交资料、成员和当前战争三类任务；已有新鲜公共缓存则直接复用。

## 2. 访问主体与安全边界

以下主体只要已经通过 `alliance_view_context`，即可请求刷新：

- 当前联盟的有效成员；
- 已登录且存在该联盟有效浏览记录的用户；
- 使用未过期联盟分享链接打开页面的访客，包括未登录访客；
- 通过平台超级管理能力读取联盟的用户，但平台管理页面仍使用独立入口和权限模型。

刷新请求不得：

- 传入当前联盟未订阅的部落标签；
- 修改 URL 或请求体来刷新另一个联盟的资源；
- 使用无效、过期或属于另一个联盟的分享令牌；
- 通过刷新读取管理字段或执行联盟管理操作；
- 在历史数据页面重新抓取或重写已归档事实。

分享令牌只用于完成本次访问校验，不写入任务载荷和审计详情。匿名分享访问的审计只记录访问类型，后续如需关联分享链接，应记录链接 ID 或摘要，禁止记录原始令牌。

## 3. 页面与资源映射

| 页面 | 是否提供按钮 | 提交资源 | 资源键 | 说明 |
| --- | --- | --- | --- | --- |
| 部落概览 / 部落详情 | 是 | `clan_profile`、`clan_members` | `clan_tag` | 概览人数、平均大本、奖杯和捐兵依赖成员同步；部落资料依赖资料缓存 |
| 联盟成员 | 是 | `clan_members` | `clan_tag` | 刷新当前免费联盟唯一部落的成员与公开资料 |
| 当前部落战列表 / 详情 | 是 | `current_war` | `clan_tag` | 只刷新当前战争；历史战争不刷新 |
| 当前 CWL 实况 / 战斗日 | 是 | `cwl_live` | `period:clan_tag` | 只允许当前活跃月份和当前联盟已配置的联赛队伍 |
| 历史战争、历史战绩 | 否 | 无 | 无 | 历史事实由归档任务维护 |
| 互刷统计 | 第一阶段否 | 无 | 无 | 互刷页面依赖成员、当前战争和汇总统计，暂不创建复合刷新入口 |

免费套餐当前只允许一个普通订阅部落和一个月度 CWL 队伍，但接口仍必须按联盟上下文校验资源，不能依赖前端隐藏来保证范围。

## 4. API 设计

普通页面统一使用：

```http
POST /api/alliances/{alliance_id}/sync-requests
X-Alliance-Share: <optional share token>
Content-Type: application/json

{
  "clan_tag": "#2QQ",
  "resource_types": ["clan_profile", "clan_members"],
  "period": null,
  "trigger": "page_open"
}
```

接口依赖 `alliance_view_context`，允许认证用户或有效分享访客调用。允许的资源类型为：

- `clan_profile`
- `clan_members`
- `current_war`
- `cwl_live`

`cwl_live` 必须携带当前月份 `period`，资源键由后端生成，前端不能直接提交资源键。其他资源不得携带月份。
`trigger` 只允许 `page_open`、`manual`、`pull_down`，用于任务载荷与审计，不改变权限、去重或冷却规则。

建议响应：

```json
{
  "alliance_id": 12,
  "clan_tag": "#2QQ",
  "results": [
    {
      "resource_type": "clan_members",
      "accepted": true,
      "reason": "queued",
      "task_id": 321,
      "task_status": "pending",
      "cooldown_seconds": 21600,
      "next_allowed_at": "2026-10-18T10:00:00+00:00"
    }
  ]
}
```

页面 GET 响应应返回 `refresh` 能力和状态，使前端无需通过失败请求猜测套餐或冷却：

```json
{
  "refresh": {
    "allowed": true,
    "resources": [
      {
        "resource_type": "clan_members",
        "state": "ready",
        "cache_updated_at": "...",
        "task_status": null,
        "next_allowed_at": "..."
      }
    ]
  }
}
```

旧管理接口继续兼容已发布版本，但新页面按钮不得调用只允许管理员的管理接口。

## 5. 冷却、去重与任务优先级

同步队列继续以 `resource_type + resource_key` 为公共身份。无论来自联盟成员、历史访问者、分享访客或另一个联盟，开放任务和冷却均共享。

主动刷新的最短间隔与付费自动刷新策略共用规则；这里的间隔是同一公共资源再次创建外部刷新任务的最短时间，
不是用户停留在页面时的自动轮询周期。

| 资源 / 状态 | 页面主动刷新最短间隔 |
| --- | --- |
| `clan_profile` | 6 小时 |
| `clan_members` | 6 小时 |
| `current_war` 无缓存、未开战或已结束 | 5 分钟 |
| `current_war` 准备日 | 30 分钟 |
| `current_war` 距开战不足 30 分钟 | 2 分钟 |
| `current_war` 战斗日 | 2 分钟 |
| `current_war` 识别为 CWL | 30 分钟 |
| `cwl_live` 当前战斗日 | 2 分钟 |
| `cwl_live` 当前月份其他活跃状态 | 30 分钟 |
| `cwl_live` 非当前月份 | 不提供页面刷新 |

已有 `pending`、`running` 或 `retry_wait` 任务时返回 `deduplicated`；冷却期内返回 `cooldown`。两种情况都不创建新任务。互动任务使用 `interactive` 优先级，但不得超过付费实时任务的 `realtime` 优先级。

资源级冷却是外部 API 成本控制的主要边界。接口还应避免同一客户端的毫秒级重复提交；第一阶段以按钮禁用、在途请求锁和公共任务去重为主，不设置按用户每日配额。

## 6. 前端交互

按钮放在页面更新时间附近，页面内容继续展示缓存，不因刷新请求而整页阻塞。进入支持页面时自动执行一次
刷新资格检查；列表型页面使用 `scroll-view` 的 refresher，详情页使用页面下拉刷新。按钮点击、顶部下拉和
页面进入最终调用同一个 API，分别记录 `manual`、`pull_down` 和 `page_open`。

状态文案：

- 可刷新：`刷新`
- 已提交或有共享任务：`正在刷新…`
- 任务成功且页面重新读取：`刚刚更新`
- 冷却中：`X 分钟后可刷新`
- 任务失败：`刷新失败，显示上次缓存`

提交成功后每 5 秒重新读取页面数据和刷新状态；任务完成、失败或离开页面时停止轮询。只禁用刷新按钮，不禁用筛选、滚动或查看详情。

## 7. 免费自动保底

免费任务不持续轮询战争中间比分，但必须保住发现和最终归档：

- 资料与成员保留 24 小时基础同步；
- 普通战在无战争或已结束时每 6 小时发现一次；发现准备日后把下一次任务排到开战后约 2 分钟，发现战斗日后排到结束后约 2 分钟；
- CWL 在月初有效窗口每 6 小时发现分组；取得 `war_tag` 后按每场开始或结束时间安排边界确认；
- 低频任务失败按 10、30、60 分钟退避，页面主动刷新仍与其他用户和付费任务共享开放任务及冷却；
- 同一部落同时被高级会员或内部联盟订阅时，全局目标自动采用更高优先级和更短间隔，免费版和普通会员只复用公共事实，不获得额外私有权限。

## 8. 普通入口与超级管理入口

普通用户页面和超级管理页面必须继续保持独立路由、权限依赖和 UI：

- 普通页面使用 `alliance_view_context` 和本设计的页面刷新接口；
- 超级管理页面不得因为普通页面刷新而复用普通成员管理入口；
- 若以后在超级管理页面增加刷新按钮，应使用平台专用 API，并在服务层复用同一个公共排队函数；
- 修改资源映射、状态文案或刷新结果结构时，必须同时评估普通页面和超级管理页面是否需要同步调整，避免两套页面行为漂移。

## 9. 失败与降级

- 同步任务失败时保留并继续展示上一次成功缓存，不写空数据覆盖旧值；
- 队列尚未进入 live 模式时返回可理解的 `planner_pending`，页面显示旧缓存；
- 单个资源提交失败不回滚同一请求中已经成功提交的其他资源；
- 外部 API 不可用时不在请求线程内重试，交给队列最大尝试次数和调度器收敛；
- 禁用页面刷新功能时，只隐藏/禁用按钮，不影响页面读取现有缓存。

## 10. 验收标准

1. 免费联盟成员、有效历史访问者和有效分享访客都能在可访问页面提交刷新；
2. 未加入联盟不是拒绝刷新的理由；
3. 无效/过期分享、错误联盟和未订阅部落标签均被拒绝；
4. 两个用户同时刷新相同资源只产生一个开放任务；
5. 页面进入、按钮和顶部下拉共用队列与冷却；冷却期内不产生新任务，并返回下一次可刷新时间；
6. 部落概览、成员、当前战况和当前 CWL 页面显示各自按钮及明确状态，内部 `scroll-view` 下拉可用；
7. 历史与互刷页面没有直接刷新按钮；
8. 刷新后数据字段权限与刷新前一致；
9. 旧管理刷新入口保持兼容；
10. 低频普通战和 CWL 能在开始/结束边界自动确认，最终事实不依赖用户记得刷新；
11. 后端目标测试和微信小程序生产构建通过。
