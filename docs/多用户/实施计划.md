# 多用户与多联盟实施计划

> 状态：M1、M2 已完成生产部署与验收；M3 与 M3.1 已完成生产迁移、后端部署和通用接口验收，
> 微信前端已随 v1.5.0 发布；M4 尚未实施
>
> 日期：2026-10-06
>
> 依赖：[账号体系设计](./账号体系设计.md)、[系统模块设计](./系统模块设计.md)

## 1. 计划目标

本计划用于把当前只服务苍穹联盟的单联盟系统，逐步迁移为支持免费单部落联盟和付费多部落联盟的多用户系统，同时保证：

- 苍穹现有功能、数据和刷新时效不因迁移回退；
- 公共 COC 数据按部落、战争和玩家全局去重；
- 联盟成员关系、角色、认证和管理数据按 `alliance_id` 隔离；
- 新用户负载不能挤占苍穹及已付费联盟的刷新资源；
- 每个阶段都可独立验收、暂停和回滚，不进行一次性整体替换；
- 尚未确认的商业规则和建议参数，不提前固化为生产行为。

本计划指定实施顺序和阶段门槛。进入某阶段前仍需用户明确授权开始该阶段；本文档本身不代表已经修改代码或生产配置。

## 2. 当前基线与主要风险

当前系统存在以下单联盟假设：

- 自有部落和部落类别主要来自 `config/settings.yaml`；
- `wechat_users.role` 是全局角色，不能表达同一用户在不同联盟中的不同身份；
- 现有 API 没有统一的 `alliance_id` 上下文；
- 小程序页面默认读取固定的自有部落集合；
- 调度器为单进程串行循环，CWL 和玩家详情等长任务会互相阻塞；
- 当前战争、联赛、成员和历史事实大多以 `clan_tag` 为公共键，适合继续全局复用，但管理评价尚未统一按联盟隔离。

实施中的最高风险依次为：

1. 权限判断遗漏造成跨联盟管理数据泄露；
2. 新调度链路影响苍穹当前战争和联赛时效；
3. 同一部落被多个联盟订阅后产生重复采集；
4. 数据迁移错误导致现有用户、角色或历史丢失；
5. 前端切换联盟后继续显示上一个联盟的缓存数据；
6. 免费用户突增导致外部 API 限流和任务积压。

## 3. 总体实施原则

采用“先建立底座，再迁移苍穹，再内部灰度，最后对外开放”的顺序：

```text
可观测性
  ↓
联盟数据模型与苍穹映射
  ↓
后端联盟上下文与权限
  ↓
前端联盟切换
  ↓
同步任务去重与队列化
  ↓
内部免费联盟灰度
  ↓
部落认证与管理权限
  ↓
外部免费灰度
  ↓
外部付费试点
  ↓
正式开放
```

贯穿所有阶段的约束：

- 数据库只做向前兼容的增量迁移，不直接删除旧字段和旧表；
- 新旧 API 在迁移期并行，先读新模型、失败可回退旧路径；
- 新同步链路先影子运行和对比，不直接接管生产刷新；
- 功能开关至少可以按全局、联盟和用户关闭；
- 公共事实继续以 `clan_tag`、`war_tag`、`player_tag` 等业务键存储；
- 私有管理记录必须显式带 `alliance_id`；
- 任何前端隐藏都不能替代后端权限校验；
- 每阶段单独提交、测试、部署和观察，不跨阶段捆绑上线。

| M2 | 后端联盟上下文与权限底座 | 旧 API 继续可用 | 越权、跨联盟和字段分级测试通过 |

| M5 | 免费单部落联盟内部灰度 | 仅测试账号开放 | 创建、订阅、手动刷新和历史复用闭环 |

## 5. M0：可观测性与回归基线

> 实施状态：M0 已完成生产部署与逐项验收。调度运行、外部请求和缓存新鲜度已有可查询基线；
> 进程重启遗留的 `running` 记录会收口为 `interrupted`，不再阻塞 M1。

### 5.1 实施范围

- 为 COC、ClashKing、腾讯文档等外部请求增加统一统计入口；
- 记录请求来源任务、接口类别、成功/失败、HTTP 状态、耗时和 429 次数；
- 记录每个调度任务的开始、结束、耗时、成功状态和失败原因；
- 记录关键缓存按部落的数据新鲜度；
- 固化当前苍穹 12 个部落的 API 返回与前端关键页面回归样本；
- 补充当前数据库备份、完整性检查和恢复演练记录。

第一阶段不改变调度频率、不新增外部部落，也不改变任何前端页面。

### 5.2 交付物

- 外部请求与任务指标表或结构化日志；
- 只读诊断接口或管理命令；
- 关键任务和页面的回归测试清单；
- 当前负载、请求量、同步延迟和失败率基线报告。

### 5.3 验收标准

- 可以按任务和接口统计每日请求量、成功率、429、平均与高分位耗时；
- 可以识别某个部落当前战争、CWL、成员资料最后一次成功更新时间；
- 指标采集失败不能阻断业务同步；
- 苍穹现有 API 返回、调度结果和前端构建不发生业务变化。

## 6. M1：联盟数据模型与苍穹租户化

> 当前状态（2026-10-09）：六张核心表、数据库约束和苍穹幂等迁移已部署生产并验收。生产库已有
> 1 个 `sky-internal` 联盟、12 个已认证自有部落和 48 个有效管理员关系；完整性检查为 `ok`、
> 外键问题为 0。现有 API、前端和调度器仍使用旧读取路径，符合 M1 不接管生产行为的边界。

当前实现采用固定 `alliance_key=sky-internal` 标识苍穹。`scripts/migrate_alliance_m1.py` 默认以
只读方式比较 12 个启用部落；应用必须显式传入 `--apply --yes`，先创建一致性备份，并可通过
`--expected-config-hash` 锁定已评审的配置版本。为保持现有苍穹用户的查看范围，迁移时已经存在的
`wechat_users` 默认建立为苍穹管理员，但不读取或修改遗留全局 `role`；人工角色文件可覆盖指定用户
为普通成员、管理员或首领。固定配置中的 12 个苍穹自有部落作为内部可信存量直接标记已认证。

生产迁移前已完成 COS 一致性备份，并由迁移工具额外保存本地 SQLite 快照。迁移重复执行不会新增
联盟、成员、部落或审计记录；API 与调度器已在同一 Git 提交上健康运行。M1 完成不代表多联盟功能
已经对用户开放，联盟上下文、字段权限和前端切换仍分别属于 M2、M3。

### 6.1 第一批数据表

先引入最小核心表，不一次性创建全部未来模型：

- `alliances`：联盟身份、名称、状态、套餐、创建者；
- `alliance_members`：用户在联盟中的角色和成员状态；
- `alliance_clans`：联盟订阅的部落、业务标签、认证摘要；
- `alliance_visits`：最近访问和默认联盟；
- `alliance_audit_events`：关键管理动作审计；
- `alliance_plans`：`free / paid / internal` 的权益快照。

约束至少包括：

- 联盟名称不是业务主键；
- `(alliance_id, user_id)` 唯一；
- `(alliance_id, clan_tag)` 唯一；
- 每个用户最多拥有一个有效免费联盟；
- 角色只允许 `member / admin / leader`；
- 成员状态和联盟状态使用受控枚举；
- 免费套餐最多一个有效部落，付费套餐暂定最多十个。

### 6.2 苍穹迁移

- 创建固定且不可复用的苍穹 `internal` 联盟；
- 把当前配置中的自有部落映射到 `alliance_clans`；
- 保留 `config/settings.yaml` 作为迁移期刷新和业务配置来源；
- 根据现有 `wechat_users` 生成迁移预览，存量用户按已确认的兼容规则默认映射为苍穹管理员；
- 可由人工角色文件覆盖首领或例外成员，应用后保存幂等迁移审计记录；
- `wechat_users.role` 暂时保留用于旧 API 兼容，但不再作为新联盟权限的最终依据。

### 6.3 验收标准

- 重复执行迁移不会创建重复联盟、成员或部落关系；
- 苍穹部落数量、Tag、类别和顺序与当前配置一致；
- 新模型读取出的苍穹范围与旧配置读取结果逐项一致；
- 回滚新读取路径后，旧系统仍可独立运行；
- 此阶段前端仍然只显示当前苍穹页面，不暴露联盟创建入口。

## 7. M2：后端联盟上下文与权限底座

> 当前状态（2026-10-10）：`1770426` 已实现 `AllianceContext`、苍穹新用户兼容加入、联盟
> 列表、联盟详情、订阅部落、成员、当前战争和 CWL 联盟范围接口；线上验收发现苍穹临时壳子
> 不属于日常 12 部落后，由 `e389c7c` 补齐迁移期 CWL 队伍归属并重新部署。旧 API 保持不变。
> 自动化测试已覆盖跨联盟角色、未认证权限封顶、访问记录不授权、退出/移除立即失效、URL
> 越权、逐字段管理数据白名单和 CWL 壳子隔离，全量 302 项测试通过。

### 7.1 API 边界

新增明确带联盟上下文的 API，不让客户端仅通过全局角色推断权限：

```text
GET  /api/me/alliances
GET  /api/alliances/{alliance_id}
GET  /api/alliances/{alliance_id}/clans
GET  /api/alliances/{alliance_id}/members
GET  /api/alliances/{alliance_id}/wars/...
GET  /api/alliances/{alliance_id}/cwl/...
```

旧接口在迁移期继续服务苍穹，新接口先只对内部测试账号启用。分享解析和微信登录属于全局接口，不强行放入联盟路径。

当前落地路径为：

```text
GET /api/alliances/{alliance_id}/wars/current[/<clan_tag>]
GET /api/alliances/{alliance_id}/cwl/live[/<clan_tag>]
```

成员接口指联盟订阅部落中的 COC 玩家，不返回微信 `openid` 或其他平台账号绑定信息。
苍穹历史 `league_teams` 中包含未列入日常 12 部落的临时壳子，M3.1 将这些月度快照幂等归属
`sky-internal`。其他联盟也通过 `alliance_cwl_seasons` 和 `alliance_cwl_teams` 显式配置当月
实战队与壳子，不要求它们加入日常订阅部落。

### 7.2 授权器

后端统一生成 `AllianceContext`，至少包含：

- 当前用户；
- 当前联盟；
- 成员状态和角色；
- 当前套餐；
- 当前部落订阅关系；
- 当前部落认证状态；
- 请求资源所需的数据级别。

JWT 只证明微信用户身份。新接口不信任 JWT 中历史遗留的全局 `role`，每次请求从数据库读取当前成员关系、认证和套餐状态。

### 7.3 字段分级

API 返回模型分为：

- `public`：允许公开和分享预览；
- `member`：当前协作信息；
- `management`：历史评价、人员决策和内部备注。

禁止先返回完整对象再依赖前端隐藏字段。管理字段必须由后端白名单组装，并同时校验联盟角色与逐部落认证。

### 7.4 验收标准

- 同一用户在不同联盟可以拥有不同角色；
- 未认证部落中，管理员和首领的业务数据权限封顶为成员；
- 修改路径参数、分享参数或本地缓存不能访问其他联盟管理数据；
- 用户退出、被移除、被封禁或降级后权限立即失效；
- 权限矩阵、逐字段输出和跨联盟隔离有自动化测试。

苍穹兼容策略为已确认例外：登录用户若从未存在苍穹成员记录，自动加入
`sky-internal` 并成为管理员；若已有成员、降级、移除或封禁记录则绝不覆盖。其他联盟的
分享加入仍为普通成员，留待分享阶段实现。

### 7.5 生产验收记录（2026-10-10）

- API 与调度器均运行在 `e389c7c`，运行提交一致、健康检查正常、服务重启次数为 0；
- `GET /api/me/alliances` 返回当前苍穹 1 个联盟及管理员角色；
- 联盟部落接口返回 12 个部落，逐部落均解析为已认证管理权限；
- 联盟成员接口返回管理级白名单且不包含微信 `openid`；
- 当前战争与 CWL 汇总分别返回 12 个部落/队伍，CWL 单队详情和 12 队切换范围正常；
- 修改联盟 ID 或请求非订阅普通战部落均返回 `404`，未携带 Token 返回 `401`；
- 公网 `https://api.skycoc.cc/api/ping` 正常，旧小程序接口在部署后持续返回 `200`；
- M2 没有数据库结构迁移，验收只更新一次被选中管理员的联盟最近访问时间；
- 本阶段未接入前端联盟切换，现有小程序页面仍使用旧接口，M3 才切换到新上下文 API。

### 8.1 页面结构

- 在顶部安全区增加醒目的联盟切换按钮；
- 显示“联盟名称（成员/管理/首领）”；
- 未认证时显示明确的“未认证”状态；
- 下拉列表只显示用户创建、加入或通过分享打开过的联盟；
- 底部 TabBar 继续保持四项；2026-10-11 的界面调整将最后一项由“设置”改为“管理”，页面路由仍保留 `pages/settings/settings`；
- 切换联盟后，部落概览/详情、成员、当前部落战和 CWL 统一使用新的 `alliance_id`；
- 联赛数据、单队联赛详情和战营联赛统计已改为读取当前联盟月度配置，不得回退读取或

  没有战营标签时显示“当前联盟无战营部落”，缓存按 `alliance_id` 隔离。

### 8.2 客户端状态规则

- 本地只保存最近选择的 `alliance_id`，角色与认证状态每次从后端返回；
- 分享链接打开时，临时切换到分享来源联盟；
- 用户没有访问权限时清理失效选择，回到联盟选择或创建页；
- 切换联盟时取消旧请求，并清空或按 `alliance_id` 隔离页面缓存；
- 页面恢复、重新登录和冷启动都必须重新验证当前联盟。

### 8.3 验收标准

- 快速来回切换联盟不会显示上一个联盟的卡片、成员或战争；
- 分享者的管理员或首领角色不会传递给接收者；
- 未登录打开分享不自动触发微信登录；
- 当前只有苍穹一个联盟时，页面行为与现网基本一致；

## 9. M4：同步解耦与全局去重

### 9.1 数据模型

引入：

- `sync_interests`：各联盟对公共资源提出的同步质量需求；
- `sync_targets`：按资源键聚合后的唯一有效同步策略；
- `sync_tasks`：持久化任务、优先级、状态、租约、重试和幂等键；
- `sync_attempts` 或等价指标记录：每次执行结果和外部请求摘要。

同一部落被多个联盟订阅时，只产生一个公共同步目标，并采用最高有效质量等级。

### 9.2 执行链路

按优先级拆分：

1. `realtime`：战斗日当前战争和正在进行的 CWL；
2. `interactive`：用户手动刷新与首次订阅的关键初始化；
3. `scheduled`：部落资料、成员列表、都城和竞赛；
4. `backfill`：历史回填、重算和非紧急修复。

先保留 SQLite 和单写者约束，通过持久化任务与有限并发 Worker 解决队头阻塞；是否迁移 PostgreSQL 或 Redis 由灰度指标决定，不在本阶段预设切换。

### 9.3 切换顺序

- 新 Planner 和 Worker 先影子运行，只计算计划、不写业务事实；
- 对比旧调度器与新 Planner 的目标、频率和请求预算；
- 先切低风险离线任务，再切普通战争，最后切 CWL 实时任务；
- 每次只接管一个任务类型，并保留关闭新 Worker、恢复旧任务的开关；
- `cwl_live` 与玩家详情、竞赛等长任务必须分离执行。

### 9.4 验收标准

- 相同资源不会因多个联盟订阅产生重复外部请求；
- Worker 崩溃后租约可恢复，不会永久卡在执行中；
- 重试有上限和退避，429/5xx 不会形成重试风暴；
- 苍穹的当前战争和 CWL 数据新鲜度不低于切换前基线；
- 可以暂停免费任务而继续保证苍穹及付费任务；
- 新旧调度路径切换和回滚至少完成一次演练。

### 12.1 开放批次

默认采用 20、50、100 个免费部落三个观察批次。该数字此前属于建议参数，每个批次开放前需要用户再次确认；未经确认不自动扩容。

每一批至少经历一个完整普通战状态变化，并覆盖一次周度任务观察。涉及竞赛月结或 CWL 月初时，需额外观察相应业务窗口。

### 12.2 每批观察指标

- 外部 API 请求量、成功率、429 和高分位耗时；
- 各优先级队列积压与最长等待时间；
- 苍穹及付费目标的数据新鲜度；
- SQLite 写锁、数据库体积、备份时间和完整性；
- 免费联盟创建、初始化、手动刷新和失败重试数量；
- 认证和权限拒绝日志；
- API 延迟、错误率和前端异常。

### 12.3 停止扩容条件

出现以下任一情况即停止下一批开放：

- 苍穹或付费联盟的刷新时效低于既有基线；
- 出现跨联盟越权或私有字段泄露；
- 最终战争事实未归档或重复归档；
- 队列持续积压且降级后仍无法恢复；
- 外部 API 429/5xx 持续升高；
- 数据库完整性、备份或恢复验证失败。

## 13. M8：外部付费联盟试点

### 13.1 试点边界

- 只接入一个外部付费联盟；
- 暂定最多 10 个部落；
- 每个部落分别完成认证；
- 未确定支付系统前，由平台人工开通固定有效期权益；
- 不承诺尚未确认的公开 SLA、赔偿或退款规则；
- 不修改苍穹现有高质量同步策略，先验证新联盟能否共享同一架构。

### 13.2 验收标准

- 1～10 个部落的订阅、逐部落认证和移除均符合配额；
- 战斗日、CWL、成员详情和管理统计达到计划刷新质量；
- 一个部落故障不会阻塞同联盟其他部落；
- 付费目标与免费目标订阅同一部落时只采集一次，并采用较高质量；
- 套餐到期或人工停用后可以降级而不删除公共历史和审计记录；
- 生产备份恢复演练能够恢复联盟、成员、认证、订阅和同步任务状态。

## 14. M9：正式开放

正式开放前必须补齐：

1. 单一付费套餐价格和有效期；
2. 支付、续费、到期和退款处理方式；
3. 是否提供 SLA、故障补偿以及具体口径；
4. 用户协议、隐私说明和付费说明；
5. 管理后台最小能力，包括联盟查询、认证争议、套餐状态、任务状态和审计查询；
6. 容量压测、上游故障、Worker 崩溃、数据库恢复和权限攻击演练；
7. 免费联盟准入配额与暂停注册开关。

未完成上述事项时，可以继续内部灰度和人工付费试点，但不能宣称正式商业开放。

## 15. 测试与验收矩阵

### 15.1 数据库

- 新库初始化；
- 现有生产库副本迁移；
- 重复执行迁移；
- 唯一键、外键和受控状态；
- 迁移前后行数与抽样字段对比；
- 备份、完整性检查和恢复。

### 15.2 权限

- 未登录、平台用户、成员、管理员和首领；
- 已认证、未认证、认证中、争议和撤销；
- 当前联盟与非当前联盟；
- 路径参数篡改、过期分享、被移除和被封禁；
- `public / member / management` 逐字段快照；
- 角色或认证状态变化后的即时失效。

### 15.3 同步

- 同一部落多个订阅去重；
- 不同质量需求取最高有效策略；
- 幂等、租约超时、有限重试和死信；
- 上游超时、429、5xx 和部分部落失败；
- 当前战争状态切换、CWL 准备/战斗/结束和最终归档；
- 免费任务降级时苍穹与付费任务继续运行。

### 15.4 前端

- 冷启动、重新登录、联盟切换和默认联盟；
- 分享进入、未登录预览和登录后加入；
- 无联盟、一个联盟和多个联盟；
- 长名称、不同角色和部分部落未认证；
- 页面返回、下拉刷新和并发旧请求；
- 微信开发者工具构建与真机验证。

## 16. 功能开关与回滚

至少准备以下独立开关，具体命名可在实现时统一：

- 多联盟新读取模型；
- 新联盟上下文 API；
- 前端联盟切换入口；
- 新 Planner；
- 各类新 Worker；
- 免费联盟创建；
- 外部分享加入；
- 部落自动认证；
- 管理字段返回；
- 付费联盟开通。

回滚顺序：

1. 关闭外部创建、分享和认证入口；
2. 暂停免费及低优先级任务；
3. 关闭发生异常的新 Worker，恢复对应旧调度路径；
4. 前端回到苍穹单联盟模式；
5. API 回退旧读取路径；
6. 保留新表、公共事实和审计记录，不执行破坏性逆迁移。

## 17. 提交与发布拆分

建议按以下独立变更提交，避免账号、调度和前端混成一个大提交：

1. 指标与回归基线；
2. 联盟核心表与幂等迁移；
3. 苍穹种子与迁移校验；
4. 联盟上下文和权限解析器；
5. 新 API 及字段白名单；
6. 前端联盟切换与缓存隔离；
7. 同步兴趣、目标和任务表；
8. Planner 与各优先级 Worker；
9. 免费联盟内部灰度；
10. 认证、冲突、移交和审计；
11. 外部免费灰度；
12. 外部付费试点。

每个提交只包含对应代码、测试和相关正式文档；前端构建产物、运行数据库、日志和凭证不提交。

## 18. 建议立即开始的第一批工作

在不需要确定价格、支付或 SLA 的前提下，第一批只实施 M0，不新增联盟数据表，也不改变生产行为：

1. 建立外部请求统计口径；
2. 建立任务耗时、失败和数据新鲜度指标；
3. 固化苍穹关键 API 与页面回归样本；
4. 形成迁移前容量基线报告；
5. 完成生产库副本的备份恢复演练。

M0 验收后再开始 M1。M1 开始前，需要先提交数据库字段级设计和苍穹用户角色迁移预览供复核；不能仅根据本文概念模型直接修改生产库。
