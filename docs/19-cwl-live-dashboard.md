# CWL 联赛实时看板设计

> 状态：第一版已实现，待真机验收。
>
> 本文描述微信小程序「战斗 → 联赛数据」的参赛部落总览、单部落战斗日、单部落联赛总览，以及「战斗 → 联赛点名」的跨部落出刀提醒。历史滚动战绩仍由 `docs/12-league-stats.md` 负责，两者不是同一功能。

## 1. 目标与范围

第一版展示当月自有联赛队伍的实时 CWL 信息：

1. 先展示当月参赛部落的粗略信息。
   每张卡片在同一行展示部落首领和当月联赛管理。
2. 点击一个部落后，进入该部落详情。
3. 详情默认打开「战斗日」，可以切换第 1～7 场。
4. 详情内可切换到「联赛总览」，查看大本、对局、成员进攻和成员防守统计。

页面顶部提供月份选择，默认北京时间当前月。后端 `available_periods` 始终返回当前月，并仅开放联赛组和全部逐场战争均完整的历史月份；切换月份时，参赛部落、详情、轮次、总览和分享参数必须一起变化。只有当前月的参赛部落预览和单部落详情执行分钟轮询；已结束历史月份首次进入时只读一次缓存，不继续自动刷新或轮询外部接口。
5. 同时支持 `combat` 实战队伍和 `shell` 壳子队伍。

第一版不把多个部落的宽表同时渲染在一个页面，避免微信小程序节点过多、横向滚动冲突和右侧列被裁剪。

## 2. 与普通部落战的边界

「部落战」和「联赛」使用不同的部落来源：

```text
战斗 → 部落战
└── config/settings.yaml → coc_sync.clans 中启用的普通战监控部落

战斗 → 联赛
└── league_teams 中当前月份的联赛队伍
    └── COC 官方联赛组和 warTag 数据确认实时状态
```

- 普通部落战页面不能决定联赛页面显示哪些部落。
- `league_teams` 是按月快照，是当月联赛队伍身份的权威来源。
- 当前 Config 可能已为下月调整，不能替代已有月份的 `league_teams`。
- Config 只可补充显示顺序、别名等非月度事实；不得用 Config 静默生成“已参赛”事实。
- 当月 `league_teams` 为空时，页面显示“本月尚未生成联赛队伍”，不回退为普通战部落列表。

## 3. 页面层级

为避免“部落总览”和详情内“联赛总览”重名，第一层统一命名为「参赛部落」。

```text
战斗
├── 部落战
├── 联赛数据
│   ├── 参赛部落（第一层）
│   │   ├── 部落 A 卡片
│   │   ├── 部落 B 卡片
│   │   └── 部落 C 卡片
│   └── 单部落详情（第二层）
│       ├── 战斗日（默认）
│       └── 联赛总览
└── 联赛点名
    ├── 集结检查（文字占位）
    └── 出刀提醒（默认）
```

### 3.1 第一层：参赛部落

```text
┌─────────────────────────────────┐
│ 战斗                 ⚔部落战  🏆联赛 │
├─────────────────────────────────┤
│ 本月参赛部落                     │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ 战营                         │ │
│ │ 冠军三 · 当前第3名           │ │
│ │ 第4场进行中 · 3胜0负         │ │
│ │ 168★ · 96.35%          ＞   │ │
│ └─────────────────────────────┘ │
│                                 │
│ ┌─────────────────────────────┐ │
│ │ 混营实战                     │ │
│ │ 大师一 · 当前第2名           │ │
│ │ 第4场准备中 · 2胜1负         │ │
│ │ 151★ · 94.20%          ＞   │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

每张卡片显示：

- 部落名称、标签和队伍别名；
- 实战队或壳子队；
- 联赛等级；
- 当前轮次和状态；
- 当前小组排名；
- 胜、负、平和进行中场次；
- 当前总星数和总摧毁率；
- 最近同步时间或同步错误。

点击整张卡片进入该部落详情。卡片顺序优先使用 `league_teams.team_index`，不依赖普通战配置顺序。

### 3.2 第二层：单部落详情

```text
┌─────────────────────────────────┐
│ ‹ 返回参赛部落                   │
│ 战营  #ABC123 · 冠军三           │
│                                 │
│   [ 战斗日 ]       [ 联赛总览 ]  │
├─────────────────────────────────┤
│ 当前子页面内容                   │
└─────────────────────────────────┘
```

- 默认打开「战斗日」。
- 战斗日默认定位当前场；全部结束后默认定位第 7 场。
- 切换「战斗日 / 联赛总览」时保留当前部落。
- 正常进入详情时默认打开「战斗日」，首个请求只下载逐场战争；首次切到「联赛总览」时才下载四张总览表，并在本页会话内保留已经加载的数据。页面重新显示时立即刷新当前可见子页，停留期间每 60 秒也只刷新当前子页，不在后台重复下载另一个 Tab。
- 参赛部落卡片和详情页头部显示“几胜几负几平”，只统计已经结束的单场；正在进行的战斗不提前计入胜负，实时领先、落后或平只在战斗日详情中展示。
- 详情头部提供大触控区域的“返回参赛部落”。
- 可在详情头部直接切换当月其他参赛部落。

### 3.3 联赛点名：出刀提醒

「联赛点名」内嵌在 TabBar 主页面 `pages/war/war`，与部落战、联赛数据共用顶部三级导航，因此底部四项主导航始终可见；内容区域使用「集结检查 / 出刀提醒」横向 Tab，默认打开「出刀提醒」。

出刀提醒集中展示当月所有联赛队伍的当前战斗日：

- 仅将当前轮次实际出现在战争阵容中的成员纳入点名，不使用报名表推断参战名单；
- 按当月 `league_teams.team_index` 固定顺序展示正在战斗的队伍，显示轮次、对手、剩余时间、已出刀人数和未出刀名单；
- 未出刀名单使用浅红背景、红色边框和红色成员文字突出显示，序号与姓名使用高亮红色，TH 与玩家标签使用较暗红色；
- 当前轮次之前已经结束的场次如仍有上阵成员漏刀，在同一部落卡片中按轮次继续展示对手和漏刀名单；历史漏刀只作留痕，使用默认灰色，不使用红色告警样式，也不计入顶部“未出刀”数字；
- 每个部落卡片可独立展开或折叠，首次进入时全部展开，页面每分钟刷新缓存后保留当前折叠状态；
- 已全部出刀的队伍仍显示，并标记“全员已出刀”；
- 当前没有战斗日时，不生成错误的未出刀名单，只汇总准备中、尚未生成联赛分组、已结束和同步异常的队伍数；
- 页面每分钟读取一次本系统缓存，倒计时在本地每秒更新，不额外调用 COC 官方接口。

「集结检查」已使用正式发布腾讯文档的月度锁定快照，与当前部落成员按昵称逐队比较；汇总卡片、单部落详情、5 分钟同步窗口和冻结规则统一见 [21-cwl-assembly-check.md](21-cwl-assembly-check.md)。它不根据 `league_teams.member_count` 或战争阵容推断到位成员。

## 4. 联赛队伍识别

### 4.1 当月候选队伍

按北京时间当前月份生成 `period = YYYY-MM`，查询：

```sql
SELECT team_index, team_alias, team_name, clan_tag,
       category, member_count, league_level
FROM league_teams
WHERE period = ?
  AND category IN ('combat', 'shell')
ORDER BY team_index;
```

缺少 `clan_tag` 的记录不能调用官方接口，应显示可见的数据异常。

### 4.2 官方数据确认

对每个有效 `clan_tag` 调用：

```text
GET /clans/{clanTag}/currentwar/leaguegroup
GET /clanwarleagues/wars/{warTag}
```

联赛组的 `season` 必须与请求月份一致。状态分为：

官方接口可能返回 `YYYY-MM-DD`（例如 `2026-10-01`），转换层必须先规范化为
`YYYY-MM` 再与页面月份比较；不能因格式差异把已经开启的联赛判成等待状态。

联赛搜索过程中，`leaguegroup` 和 `currentwar` 可能都只返回
`{"state":"notInWar"}`，没有 `season`、对手、轮次或独立的 `searching` 字段。
因此系统无法区分“尚未点击搜索”和“已经搜索、仍在匹配”这两种状态，也不得把
`notInWar` 表述为确定的“尚未开启”。只有取得当月 `season`、小组部落和轮次后，
才能确认匹配完成；搜索动作本身仍需由当月负责人在群内或操作记录中人工确认。

| 状态 | 含义 | 页面表现 |
|---|---|---|
| 待分组 | 已有当月 `league_teams`，但官方尚未返回当月联赛组；可能未搜索，也可能正在匹配 | 显示队伍卡片和“尚未生成联赛分组，可能正在搜索对手” |
| 进行中 | 赛季匹配且存在进行中的轮次 | 显示当前轮次和实时成绩 |
| 已结束 | 该组全部轮次结束 | 保留完整月度结果 |
| 未确认 | 联赛窗口内持续没有匹配赛季 | 显示“未获取到本赛季联赛数据” |
| 同步失败 | 官方接口超时或报错 | 保留旧缓存并显示错误 |

临时 404 或单次网络失败不能删除数据库中的队伍卡片，也不能清空上一次成功缓存。

## 5. 战斗日页面

### 5.1 轮次导航

内容区提供第 1～7 场横向轮次导航。每个轮次显示：

- 未开始；
- 准备日；
- 战斗日；
- 已结束；
- 轮空或无可用数据。

队伍之间的当前轮次可能不同，不能用一个全局轮次替代每个部落自己的状态。

### 5.2 战争摘要

摘要包含日期、联赛等级、轮次、状态、双方名称与标签、开始/结束时间、倒计时、双方已用刀数、星数和摧毁率，以及当前或最终结果。

### 5.3 战斗日成员表

每行按 `mapPosition` 对齐双方相同序号：

```text
序号
├── 我方：名称 / 大本 / 进攻 / 对位 / 防守 / 对位
└── 对方：名称 / 大本 / 进攻 / 对位 / 防守 / 对位
```

CWL 每位成员每场只有一刀，因此不显示普通部落战中的“第二刀”和“防守次数”列。未出刀、未被攻击和未参战必须显示为不同状态。

攻击按官方 `order` 识别；防守显示该基地本场收到的最佳攻击，比较顺序为星数、摧毁率、攻击顺序。

## 6. 联赛总览页面

单部落联赛总览由四个可折叠区块组成，每个区块使用独立横向宽表：

1. 大本概览；
2. 联赛对局；
3. 成员进攻统计；
4. 成员防守统计。

默认展开「联赛对局」和「成员进攻统计」，「大本概览」和「成员防守统计」默认折叠。页面使用原生纵向滚动，不在宽表内部再嵌套纵向 `scroll-view`。

四张宽表均只冻结名称列，而不是冻结首列：大本概览和联赛对局冻结“部落名称”，成员进攻和成员防守统计冻结“名称”。排名、等级、序号等位于名称左侧的辅助列在初始位置正常显示，横向滚动后随内容移出；名称列到达左侧边缘后使用 `position: sticky; left: 0` 吸附，并设置不透明背景、独立层级和右侧阴影，避免后方内容穿透。若微信真机对中间列 `sticky` 的支持不稳定，先保留普通横向滚动，不直接升级为多块 `scroll-view` 同步方案。

### 6.1 大本概览

```text
等级 | 部落名称 | 标签 | 总人数 | TH18 | TH17 | TH16 | ...
```

- 数据来自联赛组 `clans[].members[].townHallLevel`。
- 大本列根据实际数据动态生成并按等级降序排列。
- 每行是该联赛小组中的一个部落，不限于自有部落。

### 6.2 联赛对局

```text
当前排名 | 部落名称 | 总计 | 第1场 | 第2场 | ... | 第7场
```

每场单元格保持紧凑的单行“已出刀数 × 星数 ★ 摧毁率”，例如“`14× 42★ 98%`”；其中 `14×` 表示已经完成 14 次进攻，不是参战规模。点击任意单元格后，在屏幕中央弹出该轮双方部落名称、标签、双方成绩以及当前或最终结果；对话框四周留白并使用完整圆角和阴影，点击遮罩空白处或右上角“关闭”均可收起。后端通过 `opponent_tag` 精确匹配对手行，未取得对手时显示“对手待定”。准备日单元格显示“准备中”，未开始显示“—”。表格不重复展示结果文字，而是用字体颜色表达状态：已结束的胜、负、平分别使用标准高亮绿、红、黄；进行中的领先、落后、平使用更淡的低饱和度绿、红、黄，避免被误认为最终结果；准备中和未开始为灰色。只有状态为 `war_ended` 的场次才累计“胜 / 负 / 平”；进行中的优势不能提前计入胜场，也不能提前增加 10 颗胜场奖励星。实时进攻星和摧毁率仍参与当前排名。轮次表头显式生成 `1..N`，不得出现“第0场”。总计与排名通过同组 warTag 明细计算，算法必须是无 I/O 的纯函数并使用固定测试样例覆盖并列场景。

第一版不显示以下无法由当前官方数据可靠确认的字段：

- “晋级 / 保持 / 降级”：进行中只能预测，且不同段位规则需要独立维护；
- “额外”：截图中的奖励名额含义和当前规则不能从战争明细直接确认。

### 6.3 成员进攻统计

```text
排名 | 名称 | 大本 | 总计 | 出刀数 | 对位差 | 第1场 | ... | 第7场
```

- 统计至少进入过一场战斗日阵容的成员。
- 每场单元格显示星数和摧毁率。
- 未参战显示“未参战”，进入阵容但未出刀显示“未出刀”。
- 总计显示累计星数、累计摧毁率和实际出刀数。
- 排名先按总星数降序，再按累计摧毁率降序；仍相同则按玩家标签稳定排序。
- 第一版不显示“联赛币”：官方战争数据不能确认个人最终获得的基础奖励和额外奖励。

对位差定义为：

```text
自己的地图序号 - 进攻目标地图序号
```

- 正数：向上打，例如 15 号攻击 5 号为 `+10`；
- `0`：同号；
- 负数：向下打；
- 总对位差为所有实际进攻的差值之和，未出刀不参与。

### 6.4 成员防守统计

```text
排名 | 序号 | 名称 | 大本 | 防守成果 | 防守成功 | 第1场 | ... | 第7场
```

每个成员按实际进入阵容的场次数作为统计分母。每场只取该基地收到的最佳攻击；同一场被多次攻击不会重复扣除防守成果。

```text
保住星数 = 3 × 参战场数 - 各场最佳来袭星数之和
保住摧毁率 = 100% × 参战场数 - 各场最佳来袭摧毁率之和
```

例如显示 `5★ 117%`，表示累计保住 5 星和 117 个百分点的摧毁率。

“防守成功”第一版定义为：被进攻且未被三星的场数 / 进入阵容场数。未被攻击单独显示“未被打”，不算一次防守成功。

防守排名先按保住星数降序，再按保住摧毁率降序；仍相同则按玩家标签稳定排序。

## 7. 缓存与增量同步

实时联赛看板不能直接使用 `league_results`：该表是历史成员汇总，缺少分组、轮次、地图序号和逐场完整攻防明细。

第一版已新增两个缓存边界，DDL 统一放在 `shared/db/connection.py`：

### 7.1 联赛组缓存

表名：`cwl_live_group_cache`。

每个 `(period, clan_tag)` 一行，保存 `team_index`、队伍显示信息、官方 `season/state`、标准化联赛组 JSON、最近成功时间和最后错误。

### 7.2 联赛战争缓存

表名：`cwl_live_war_cache`。

每个 `war_tag` 一行，保存 `season`、战争状态、标准化战争 JSON、最近成功时间和最后错误。以 `war_tag` 去重，避免两个自有部落处于同一小组时重复保存或重复计算同一场战争。

### 7.3 增量规则

- 联赛组数据只覆盖同月同部落的缓存。
- 第一轮 `preparation` 平时每 30 分钟刷新，距开战不超过 30 分钟时提升为每 2 分钟。
- 第二轮及以后 `preparation` 首次保存后按 30 分钟兜底刷新；上一轮任一战争刚确认结束时，立即刷新下一轮，不持续高频轮询重叠的准备日。
- `inWar` 战争按 2 分钟活跃频率刷新。
- 已成功同步为 `warEnded` 的战争视为不可变，不再重复拉取。
- 未来轮次可先保存 warTag，在接近对应轮次时再获取详情。
- 单个部落或单个 warTag 失败必须隔离，保留其他队伍和上一份成功数据。
- API 只读缓存，页面请求不得直接批量访问 COC 官方接口。

### 7.4 历史月份回填

实时同步上线前遗漏的月份，可使用 `scripts/backfill_cwl_live.py` 从 ClashKing
历史 CWL 战争日志重建上述两张缓存表。该流程仅用于一次性历史修复，不加入周期调度：

1. 以当月 `league_teams` 的 `combat` / `shell` 队伍为入口；
2. 从自有部落的历史对手推断完整联赛组，再拉取组内各部落战争日志；
3. 按战争标签去重，并校验组规模、轮次数、每轮场数和每个部落每轮恰好出场一次；
4. 有 `league_results` 历史汇总的队伍，逐成员核对累计星数和出刀数；
5. 全部队伍通过后才允许在单个事务中写库，任一队失败都拒绝写入。

默认运行是只读 dry-run；`--apply` 才写库，且目标月份只要已有任一实时缓存记录就拒绝覆盖。
历史回填记录在标准化 JSON 中标记 `source=clashking_history_backfill`，与官方实时同步来源可区分。
战争日志能够还原实际每轮阵容、进攻、防守与排名；没有进入任何一轮阵容的报名成员不在历史战争日志中，
因此不能用该数据源反推完整报名名单。

## 8. 刷新策略

联赛仅在每月月初开放，第一版按北京时间执行：

| 阶段 | 后端同步策略 |
|---|---|
| 每月 1～12 日，尚未获取联赛组 | 每个待确认队伍最多每 30 分钟查询一次 |
| 第一轮准备日 | 每 30 分钟刷新；距开战不超过 30 分钟时每 2 分钟刷新 |
| 第二轮及以后准备日 | 首次保存后每 30 分钟兜底；上一轮刚结束时立即刷新一次 |
| 战斗日 | 当前轮次战争每 2 分钟刷新 |
| 单场已结束 | 成功缓存后停止刷新该 warTag |
| 整组已结束 | 保留缓存，本月不再主动刷新 |
| 每月 13 日至月底 | 不访问官方联赛接口，只提供缓存读取 |

历史回填不受 1～12 日同步窗口限制，但必须由运维人员显式 dry-run、备份数据库后执行。

新增独立调度任务 `cwl_live`，不改变现有每月历史归档任务 `cwl` 的语义。调度实现仍归 `scripts/scheduler.py` 管理，不启动新的常驻进程。

前端进入页面、返回前台时读取一次缓存；停留期间每 1 分钟读取一次。单部落详情只请求当前可见的 `war-day` 或 `overview` 数据，另一个子页在首次切换时再加载；两个子页分别记录最近一次 `updated_at`，轮询返回时间未变化时不替换详情对象，避免逐场阵容和四张总览宽表无效重绘。前端轮询只访问本系统后端，不增加 COC 官方请求次数。

## 9. API 设计

已实现：

```text
GET /api/clan/cwl-live
GET /api/clan/cwl-live/{clan_tag}?round=4&view=war-day
GET /api/clan/cwl-live/{clan_tag}?view=overview
GET /api/clan/cwl-check-in
```

联赛汇总接口返回当月参赛部落卡片、同步状态和更新时间。详情接口按 `view` 拆分：`war-day` 返回指定部落的轮次战争，`overview` 返回大本、对局、成员进攻和成员防守四类统计；两者都返回头部摘要和当月可切换队伍，不传 `view` 的完整响应只用于兼容旧版小程序。点名接口只聚合当月联赛组和逐场战争缓存，返回所有队伍当前战斗日的实际阵容、出刀进度、未出刀成员，以及当前轮次之前已结束场次的漏刀记录；请求路径不访问 COC 官方接口。

- 路径参数只能匹配当月 `league_teams` 中的部落标签。
- 未验证的标签不能透传到 COC 官方接口。
- 所有小程序用户均可查看，不要求绑定游戏账号。
- COC Token 只存在于后端环境变量中。

## 10. 分享

- 分享「参赛部落」时，接收者打开当月全部参赛部落列表。
- 分享单部落「战斗日」时，接收者直接打开该部落和当前选中轮次。
- 分享单部落「联赛总览」时，接收者直接打开该部落的总览 Tab。
- 分享「联赛点名」时，接收者打开分享时选中的「集结检查」或「出刀提醒」Tab；出刀提醒仍读取最新缓存，不分享静态名单。
- 分享的是最新数据入口，不是静态数据快照。

使用非 TabBar 落地页：

```text
/pages/war/cwl-detail?clan_tag=%23ABC&view=battle&round=4
/pages/war/cwl-detail?clan_tag=%23ABC&view=overview
/pages/war/war?tab=check-in&check_in_view=attack
```

## 11. 小程序表格约束

复用 `docs/11-uni-app.md` 和 `docs/18-current-war-dashboard.md` 已验证的规则：

1. 使用普通 `<style>`，不使用 `<style scoped>`。
2. 表头和每行显式设置横向 flex。
3. 单元格固定宽度并设置 `flex-shrink: 0`、`box-sizing: border-box`。
4. 表头、数据行和内部背景容器使用相同总宽度。
5. 页面负责纵向滚动，每张宽表只使用一个 `scroll-view scroll-x`。
6. 不嵌套横向和纵向 `scroll-view`。
7. 不在第一版实现冻结首列、复杂 `sticky` 或单元格合并。
8. 四张总览表按区块折叠，避免一次创建全部表格节点。

## 12. 错误与边界情况

| 场景 | 页面处理 |
|---|---|
| 当月无 `league_teams` | 本月尚未生成联赛队伍 |
| 队伍缺少 `clan_tag` | 显示数据配置异常，不调用外部 API |
| 官方仅返回 `notInWar` | 显示“尚未生成联赛分组，可能正在搜索对手”，不推断是否已点击搜索 |
| 官方赛季与当前月份不一致 | 不混入当前月，显示未获取本赛季数据 |
| 单个队伍同步失败 | 保留旧卡片和缓存，显示错误时间 |
| 某个 warTag 同步失败 | 仅该轮次显示暂不可用 |
| 本轮轮空 | 显示轮空，不渲染成员表 |
| 成员未进入阵容 | 总览单元格显示未参战 |
| 成员进入阵容但未出刀 | 显示未出刀 |
| 基地未被攻击 | 显示未被打，不算防守成功 |
| 联赛结束 | 本月继续展示最终结果，停止主动刷新 |

至少覆盖以下自动化测试：

- 当月 `combat` 和 `shell` 队伍均能进入候选列表；

- API 不接受当月队伍之外的标签。
